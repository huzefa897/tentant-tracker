# Testing with fakes

The rules (tests ship with every change, where they live, what to assert) are in `CLAUDE.md`. This covers the shared fakes and fixtures.

Tests never touch Firebase or the API: mock the services with the shared fakes, `vi.mock('@/services/auth.service', () => import('@/test/mocks/authService'))` and the same for `access.service`, `tenant.service` and `rentEntry.service`, calling `resetAuthService()`/`resetAccessService()`/`resetTenantService()`/`resetRentEntryService()` in `beforeEach`. `dashboard.service` is mocked for **every** test by `src/test/setup.ts` (the dashboard is where sign-in lands) with `src/test/mocks/dashboardService.ts`, reset before each test: it filters and pages `fakeDashboard.periods` like the API, returns `fakeDashboard.summary`, and `markNotOwed` removes the month from the list; build rows with `makePeriod` (prepared), `makeUnbilledPeriod` and `makeSummary`. `getOverdueBills` filters and totals `fakeDashboard.overdueTenants` (build them with `makeOverdueTenant` and `makeOverdueBill`; `overdueBills(filters)` is the response). Its own spec uses the real service (`vi.unmock`). Mock `payment.service` with `src/test/mocks/paymentService.ts` (its `reversePayment` marks the payment reversed as `REVERSED_BY`, voids its fake receipt and leaves it out of the bill's figures; the same reason again is a retry, another is `reversal_conflict`) and `receipt.service` with `src/test/mocks/receiptService.ts` (one receipt per fake payment, kept in `fakeReceipts`; issuing again returns it, and issuing for a reversed payment without one is `payment_reversed`); `resetRentEntryService()` resets both. Mock `@/utils/receiptDownload` in view tests: jsPDF needs fonts fetched over the network.

- **Sign-in and access:** `signInAs()` sets the session Firebase "restores"; the default identity has one property, so protected pages open directly.
- **Tenants:** the tenant fake searches and pages its fictional `testTenants` (ids `tenant-001`…) like the API; `fakeTenancies` changes them or the page size, and `loadTestTenants()` (`src/test/tenants.ts`) signs in, selects the property and loads them for store tests.
- **Bills:** the rent entry fake saves, filters and pages `fakeEntries.entries` like the API (409 for a duplicate month). `fakeEntries.rate` makes the "server" charge another rate, and `fakeEntries.rent` another rent when the form left it unedited. Bills' payments live in `fakeEntries.payments` (add them with `addFakePayment`, so the bill's figures follow); the payment fake checks the balance and remembers idempotency keys like the API (a retry returns what the key recorded). Bills are voided (`voidEntry`) and corrected (`correctEntry`, remembering its keys) like the API: refused while a payment counts (`unreversed_payments`), a void bill takes no payments (`entry_void`), a correction that changes nothing is refused, and lists show active bills unless `billStatus` asks for void ones, newest month then newest created first. Build bills with `makeEntry` (`src/test/rentEntryFixtures.ts`, re-exported by `src/test/rentEntries.ts`): its figures follow its charges unless overridden, and `billStatus: 'void'` gives it void details and a void bill's figures. Fakes import fixtures from `rentEntryFixtures.ts`, never `rentEntries.ts`, which imports the router (a cycle through the mocked service).
- **Router:** it's shared across tests: navigate with `force: true` when the path may already be current.

## Layout tests

jsdom lays nothing out, so a test there can't tell whether an amount overlaps its neighbour. `*.layout.spec.ts` files (in `__tests__/`, next to the jsdom spec) run in headless Chromium instead: `npm run test:layout` (`vitest.layout.config.ts`, Vitest browser mode with Playwright; `npm test` leaves them out). First run `npx playwright install chromium` once. CI runs them in their own `layout` job.

- Mount with `mountAt({ viewport, width }, (attachTo) => mount(Component, { props, attachTo }))` (`src/test/layout.ts`): it sets the viewport (so Tailwind's breakpoints apply), puts the component in a box `width` px wide (the card it sits in; leave it out for the full width), loads the app's CSS and waits for Poppins, failing if it didn't load, since a fallback font would measure differently. Call `unmountAll` in `afterEach`.
- Assert with `overflowing(elements)` (the ones whose content is wider than their box, with both widths, so a failure says by how much), `isShown(element)` and `document.documentElement.scrollWidth` (no sideways scroll on the page). Use the largest values the app allows (a 12-digit amount), and fake data only.
- Covered so far: the overdue bills table (`OverdueTenantList`, at its 60rem minimum and in a narrower card, and the rows below `xl`) and the page totals (`RentEntryTotals`, from 320px to 640px). Check that a new test fails without the fix it guards.
- A failure saves a screenshot under `.vitest/` (gitignored).

Backend tests mock `verify_firebase_token` and never call live Firebase; the concurrency tests need PostgreSQL. The Sheet converter's and admin import's tests build fictional workbooks with `openpyxl`. They run through `config/test_runner.py`, which uses a dummy cache (so rate limits never carry over between tests; rate-limit tests override `CACHES` with a real one and patch `SimpleRateThrottle.THROTTLE_RATES`) and silences console log output (`assertLogs` still works). The admin login throttle counts in the database, so each test starts from zero; its concurrency test, like the billing ones, needs PostgreSQL.
